A UI language that checks what it is allowed to do.

A component declares the authority it needs, and the compiler, not a code review, refuses the program when the code asks for more.

Try itWhy it is differentSee the language
the terminal
$ cancho-ui check clock.cui          # `requires Clock;` deleted
error[capability-missing] clock.cui:13:21: component `Clock` performs `clock.now`
  which requires the `Clock` capability, but `requires Clock` is not declared
exit 1

$ cancho-ui check examples/clock/clock.cui
exit 0

$ cancho-ui inspect effects examples/clock/clock.cui Clock --output json
{ "component": "Clock",
  "reachable_effects": [ { "capability": "Clock", "path": ["clock","now"], ... } ] }

Real output of the compiler. The refusal carries a stable code, a span and a remediation in --output json, so an agent matches on the code instead of reading prose.

Behaviour and authority, in the source

State, events, effects and permissions are part of the language, so tools can answer questions about them.

🔐

Declared capabilities

requires Network; is the only way a component reaches the network. A missing or unused declaration is refused.

🧾

Diagnostics as data

A locked JSON shape with a stable code, a span and a remediation. The CLI's exit codes are a contract too.

🛑

Async that cannot go stale

A superseded request is dropped at the await. A disposed component gets Cancelled in its own mandatory match arm.

🌐

Plain output

JavaScript and the real DOM. No virtual DOM, no JSX, no macros. The page owns presentation.

What a component looks like

Block-structured and readable in a review. A lightly trimmed examples/clock, which compiles and runs.

component Clock {
    requires Clock;

    state started_at: Int = 0;
    state ticking: Bool = false;

    on Start { started_at = clock.now(); ticking = true; }
    on Stop  { ticking = false; }

    view {
        Column {
            Text { role: status label: "elapsed time"
                   "Elapsed: {(clock.now() - started_at) / 1000}s" }
            Button { label: "Start" on: Start }
            Button { label: "Stop"  on: Stop  }
        }
    }
}

Nine more examples are in examples/: a counter, a searchable list with cancellation, composed components, cross-file imports and component disposal.

Measured, not promised

What the repository can show today.

10example programs compile and run
108tests pass under cargo test --workspace
~26,000mutated programs (every prefix, every one-character deletion) refused or accepted, never a panic
0clippy warnings under -D warnings

Not measured: whether an agent is more productive with cancho-ui than with a conventional stack. That needs the Phase 3 benchmark, which has not been run. There is a semantic diff (authority, state, events, effects; not full behavioural equivalence), but no replay and no mobile backend yet; see the roadmap.

Try it

You need a Rust toolchain; the version is pinned in rust-toolchain.toml.

git clone https://github.com/alpibrusl/cancho-ui.git
cd cancho-ui
cargo build --release
target/release/cancho-ui build examples/clock/clock.cui -o examples/clock/clock.js
cd examples/clock && python3 -m http.server     # serve it, then open /clock.html

The python3 line only serves the page to your browser. The compiler and the emitted code do not use it.
