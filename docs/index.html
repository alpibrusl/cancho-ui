Behaviour and authority, in the source

  
State, events, effects and permissions are part of the language, so tools can answer questions about them.

  

    
🔐
Declared capabilities
requires Network; is the only way a component reaches the network. A missing or unused declaration is refused.

    
🧾
Diagnostics as data
A locked JSON shape with a stable code, a span and a remediation. The CLI's exit codes are a contract too.

    
🛑
Async that cannot go stale
A superseded request is dropped at the await. A disposed component gets Cancelled in its own mandatory match arm.

    
🌐
Plain output
JavaScript and the real DOM. No virtual DOM, no JSX, no macros. The page owns presentation.

  






  
What a component looks like

  
Block-structured and readable in a review. A lightly trimmed examples/clock, which compiles and runs.


component Clock {
    requires Clock;

    state started_at: Int = 0;
    state ticking: Bool = false;

    on Start { started_at = clock.now(); ticking = true; }
    on Stop  { ticking = false; }

    view {
        Column {
            Text { role: status label: "elapsed time"
                   "Elapsed: {(clock.now() - started_at) / 1000}s" }
            Button { label: "Start" on: Start }
            Button { label: "Stop"  on: Stop  }
        }
    }
}

  
Every example is in examples/ (23 programs): a counter, a stopwatch, a searchable list with cancellation, composed components, cross-file imports, notes in Storage, a machine console and more. Ten of them run live in the gallery.

Measured, not promised

  
What the repository can show today.

  

    
23example programs compile, and 19 of them replay a recorded trace

    
390+tests pass under cargo test --workspace

    
~26,000mutated programs (every prefix, every one-character deletion) refused or accepted, never a panic

    
0clippy warnings under -D warnings

  

  
Not measured: whether an agent is more productive with cancho-ui than with a conventional stack. That needs the Phase 3 benchmark, which has not been run. There is a semantic diff (authority, state, events, effects; not full behavioural equivalence) and a deterministic test replay of event traces (handlers only, with a scripted network and a fake clock; not the view, not timing, and a second implementation of the semantics rather than the emitted JavaScript), but no mobile backend yet; see the roadmap.






  
Ask your coding agent to try it

  
Paste this into Claude Code, Codex or any coding agent that can run commands. It installs cancho-ui, proves the install with the test suite (no network, no key, no model), and walks through a refusal and a diff.

  

    
prompt raw

    
Install cancho-ui and try it on one small program. Work in a new empty directory, keep every path free of spaces, and never use sudo. Run steps 2 to 5 in one shell session. Report honestly; do not retry a failing command in a loop and do not edit the repository to make a command pass.

1. Check that `git`, `cargo` (Rust, via rustup) and a C linker (`cc`) exist. If one is missing, stop and tell me which; do not install system packages on your own.

2. Get the repository:
   git clone https://github.com/alpibrusl/cancho-ui.git
   cd cancho-ui

3. Build it and prove the install works. This needs no network after the clone, no key and no model:
   cargo build --release
   cargo test --workspace          # every line `test result:` must say ok, none failed
   export CUI="$PWD/target/release/cancho-ui"

4. Try the compiler on its own example, a clock component that declares `requires Clock;`:
   "$CUI" check examples/clock/clock.cui ; echo "exit $?"                      # expect exit 0
   "$CUI" inspect effects examples/clock/clock.cui Clock --output json        # the capability and where it is used
   Now make a copy without the declaration and check it:
   sed '/requires Clock;/d' examples/clock/clock.cui > /tmp/no-cap.cui
   "$CUI" check /tmp/no-cap.cui ; echo "exit $?"                                # expect capability-missing, exit 1
   "$CUI" check /tmp/no-cap.cui --output json                                   # the same refusal as data (code, span, remediation)
   Then compare two programs. Use examples/clock/clock.cui and examples/counter/counter.cui:
   "$CUI" diff examples/clock/clock.cui examples/counter/counter.cui ; echo "exit $?"     # expect exit 5 (the programs differ)
   "$CUI" diff examples/clock/clock.cui examples/clock/clock.cui ; echo "exit $?"         # expect "no semantic change", exit 0
   Then replay a trace of events with no browser. The trace resolves a slow earlier search after a newer one; the stale answer must be dropped:
   "$CUI" test examples/search/search.cui examples/search/stale.trace.json ; echo "exit $?"   # expect PASS, exit 0

5. Build the counter to JavaScript and look at it in a browser:
   "$CUI" build examples/counter/counter.cui -o docs/demo/counter.js
   python3 -m http.server -d docs 8000        # only serves the files; then open http://localhost:8000/demo/counter.html
   Click Increment twice and Reset. If you cannot open a browser, say so and stop after the build.

6. Tell me, briefly:
   - the exit code and the first line each command printed in step 4;
   - whether `cargo test --workspace` passed, and how many tests;
   - what the counter did in the browser, or that you could not open one;
   - anything that failed, with the exact error.
Docs: README.md (the commands), docs/semantic-diff.md (what diff compares), docs/replay.md (what test replays, and what it does not), spec/diagnostics/README.md (the refusal shape).

  

  
It needs no key and no model. The same text is in docs/agent-prompt.md, and a Claude Code skill that teaches an agent to check, inspect and diff .cui programs is in skills/cancho-ui.





  
Try it

  
You need a Rust toolchain; the version is pinned in rust-toolchain.toml.


git clone https://github.com/alpibrusl/cancho-ui.git
cd cancho-ui
cargo build --release
target/release/cancho-ui build examples/clock/clock.cui -o examples/clock/clock.js
cd examples/clock && python3 -m http.server     # serve it, then open /clock.html

  
The python3 line only serves the page to your browser. The compiler and the emitted code do not use it.
