# Dropped, or changed on purpose

The port is not a copy of the page: where a feature of the page does not carry over, the port says so here, with what it does instead and what undoing it would take. **Each row is a decision the user can
overturn**; they are the recommendations J1 to J9 of [`gaps.md`](gaps.md) section 7, taken as the coordinator decided on 2026-10-26 ("go with your recommendation on each, and record every one that drops or
changes visible page behaviour"). The numbers are the ones `parity-rules.json` cites. B1 is this PR (content, head, theme, data, pictures, videos, the pane); B2 is the islands and the map.

| # | what the page does | what the port does | why | to undo it | call |
|---|---|---|---|---|---|
| 1 | A **human / agent switch** in the header hides the whole page and shows `agents.md` in a `<pre>` (`#agent-view`); the "For agents" section says "Flip the switch in the header". | **No switch, no agent view.** The `#agents` section stays with its five endpoints and the pane that reads `agents.md`, `data/ecosystem.json` and `llms.txt`; the sentence about the switch is gone. | Hiding static sections by state is not something the prerenderer does (an `If` around them would leave a page that is empty without script). | A design note first: a `hidden:` on static elements that the page's HTML writes in its first state and the script updates (it touches the rule that script never writes a static node). | J4 |
| 2 | Icons and an image in links: the logo mark in the brand link, the star in the GitHub link, the three bars of the menu, five icons of the trust chain. | **No icons, no logo in the link**: the brand is the word "cancho", the GitHub link says "GitHub", the menu button says "Menu", the chain has none. (The logo is still the page's icon and touch icon.) | An image inside a `Link` or a `Summary` is refused (`rich-child-invalid`); SVG is not accepted as a picture. All decoration, `aria-hidden` on the page. | Allow an `Image` in a `Link`, and a pinned SVG element with a closed allow-list (`Drawing`): two features, each a design. | J2, J3 |
| 3 | The inline links of the header (8) are shown from 62 rem, and a menu with the same links below; the GitHub link is hidden under 30 rem. | **The menu is the only navigation, at every width** (a `Details` that holds one `Nav` of nine links); the header has the brand, "Pre-1.0 · alpha", the GitHub link and the menu. On a phone and on a desktop alike. | A link cannot be shown or hidden by width: that is a viewport rule, which the program does not say. One list of links, not two. | A `Nav` that collapses under a width: one use does not make a feature; ask for it. | J5 |
| 4 | The pull quote is a `<blockquote>` with a `<cite>`. | A `Figure` with the quote and a `Caption` naming the author and the article. | One use; no new element. The accessibility tree has a figure where the page has a blockquote. | A `Quote` element. | J6 |
| 5 | The pane for agents is a separate program (`ui/agent-files.cui`, compiled to `assets/agent-files.js`) and the page says so, with a link to its source. | The pane is **a component of the page's own program** (`AgentFiles`, `requires Network;`), and the sentence says that. Its buttons say which file is shown (`pressed:`). | The whole page is one program now. | Nothing to undo: it is how the port is built. | |
| 6 | The five links of the trust chain show the numbers 1 to 5 in a span, beside an ordered list. | The `<ol>` numbers its own items; no span. | Two numberings are one too many. | Add a `Text` to each item. | |
| 7 | The comparison table (`role=table` on divs) has an empty first column header. | A real `<table>`; the first column header is "Question". | An empty header cell has no name for a screen reader. | Remove "Question". | |
| 8 | The three cards under the h1 are **h3**: the outline of the page goes h1, h3, h3, h3, h2. | They are **h2**. | `heading-level-skipped`: the compiler refuses a skipped level, and the page's outline had a hole. | Nothing: cancho-ui does not allow it. | J1 |
| 9 | Hover effects (15 rules: cards and links lift, pictures zoom), the stagger of the reveals, rounded corners of the waffle's squares, the copy button strips `# comments` from what it copies. | None of them. The copy button copies the text as it is shown (`structure.md` section 8). | Not expressible, or a rule of the page's own script. | None is a feature the language has. | J9 |
| 10 | The look: the page's 106 classes and 19 viewport rules. | The compiler's baseline with the page's palette and three fonts (the theme): colours and fonts are the page's, the layout is not. The pixel diff (B3) says how far apart they are. | `presentation.md`: a program says what a thing is, the stylesheet says how it looks. | A design for a handful of roles (`Card`, the header's arrangement). | J9 |
| 11 | **The authority animation**: tabs, a code pane with the current line lit, a stepper of three glyph buttons (`◀ ▶ ▶\|`) with an `aria-label` each, a row of dots, a caption in a live region, a verdict, auto-play when the section is first seen. | The tabs, the code lines, the caption and the verdict are **text of the program** (from `data/authority.json`), the canvas is a sealed frame that reads `scenario` and `step` from the state. The stepper is **three text buttons** (Previous step, Play/Pause, Next step); **no dots**; the lit line is marked "▶ " (a refused line "✗ "), not coloured; Play goes on by itself every 2.6 s (a schedule), **and does not start by itself when the section is first seen**. | The text is now replayable, readable and in the accessibility tree; a visible label is the name (WCAG 2.5.3); starting by itself needs an `on Visible` that starts a schedule, which was not built for one use. | Glyph labels need `Button` to have a visible text different from its name; auto-play needs `visible:` to start a handler (it can: `visible: Seen` and `on Seen { playing = true; }`: not done, said). | J7 |
| 12 | **The drawings**: the hero, ten cairns, three card drawings (inline SVG, CSS animation, JetBrains Mono in the cards). | The hero is the page's own `rocks.js` and `scene.js` in a sealed frame (byte for byte), with the pointer fed by the runtime; the cairns, the three cards and the canvas are frames of their own. **The cairns do not settle when seen** (a frame cannot tell it is on screen; they are drawn at rest); **the card drawing with text uses the system monospace font** (a frame loads no font); the drawings are named by the frame's title and not by a `role=img`. | A sealed frame reaches nothing but the page. | An `on-screen` prop for frames (the pointer one exists) would give the cairns their settle back. | J3 |
