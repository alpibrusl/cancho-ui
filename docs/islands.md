# Islands: the hero, the cairns and the map, declared and measured (addendum to `www.md` section 6)

> **Status: the sealed island (section 11) and the open island (section 12) are built (2026-10-25).** What follows is the design addendum, corrected in place where the build found it wrong (each correction says so). `www.md` section 6 designed islands; section 10 item 3 decided that the map is an **open** island (`authority` prints `UNBOUNDED`) and the hero and the cairns are **sealed**. This note takes the real files of cancho-www (`dbbf7ae`: `rocks.js` 5,524 B, `scene.js` 3,304 B, `map.js` 21,760 B, the rules of `site.css`) as the worked examples, **measures** what a sealed island can and cannot do, and answers what the smallest island API is.
> Measured in **desktop Chromium** (Playwright, the `Pixel 7` profile is a viewport and a user agent, not a device) by [`scripts/measure-islands.js`](../scripts/measure-islands.js), which takes a clone of cancho-www and prints every table below (`node scripts/measure-islands.js <clone> [reach|messages|spin|hero|pointer|cairns|media|a11y|hydrate|race]`). "4x" is Chromium's CPU throttle, a proxy and not a phone. The machine was shared, so timings under throttle vary from run to run; where a number moved between two runs both are given.

## 1. What the measurements changed in `www.md` section 6

Corrected there too, each with the measurement behind it:

1. **The CSP of section 6 does not seal the frame.** *(As built the frame's own policy also names its scripts by hash instead of `'unsafe-inline'`: section 11.)* With `sandbox="allow-scripts"` and `default-src 'none'; script-src 'unsafe-inline'; style-src 'unsafe-inline'` the island **navigated its own frame to another origin** (`location.href = ...`: **1 request arrived there**) and a `<meta http-equiv="refresh">` it added did the same (1 request). Adding `form-action 'none'; base-uri 'none'; frame-src 'none'` **to the frame's CSP does not close either** (still 1 request each). What closes both is the **page's own CSP: `frame-src about:`** (0 requests). So a page with an island needs a CSP `<meta>` of its own, merged with the one a map already gets (`img-src`).
2. **WebRTC leaks.** An island that opens an `RTCPeerConnection` to a STUN server sent **3 UDP packets** to it in every configuration above; CSP does not govern ICE. A shim written before the island's script, that makes `RTCPeerConnection`, `webkitRTCPeerConnection` and `RTCDataChannel` `undefined` and non-configurable, made it throw `TypeError` and **0 packets arrive**. That closes the way I tried; it is not a proof that no other way exists (see 9).
3. **"Bounded authority" is not bounded time.** A sealed island that loops for 2 s stalled the page: the longest gap between two frames of the *page* went from 17–67 ms to **1,983 ms**. The sandbox bounds what an island can *reach*; it does not bound what it costs. A sealed island can freeze the page it is in, and the design must say so.
4. **`size: Responsive { ratio: 640 / 600 }`** is `width: 640 height: 600`, as for `Image` (16:15 is not in the closed `ratio` set, and the integer pair gives the aspect ratio before the frame loads).
5. **`requires Draw`** is dropped. A sealed island reaches nothing but the page, by messages (section 2): a capability that grants nothing is noise in `authority`. A sealed island is **listed** (section 6), an open one declares **`requires Dom`**.
6. "The pointer is forwarded as a message" has a cost, measured in 3, and a rule: at most 20 a second.

## 2. What a sealed island can reach, measured

An island script runs in `<iframe sandbox="allow-scripts" srcdoc="...">` and tries 30 things; a second HTTP server on another port and a UDP socket record what arrives. Four configurations: (1) the CSP of `www.md` section 6; (2) = (1) + `form-action 'none'; base-uri 'none'; frame-src 'none'` in the frame; (3) = (1) + the page's own CSP `frame-src about:`; (4) = (2) + (3) + the shim of 1.2.

**Nothing arrived, in all four configurations,** for: `parent.document` and `top.location` (`SecurityError`), `localStorage`, `document.cookie`, `indexedDB` (`SecurityError`), `fetch` to another origin and to the page's own (`TypeError`), `XMLHttpRequest`, `new Image().src`, `sendBeacon`, `WebSocket`, `EventSource`, a `<link rel=stylesheet>`, a CSS `url()`, a `<script src>`, `import()`, a nested `<iframe src>`, a `<form>` submitted (the sandbox has no `allow-forms`), `window.open` (`null`), an `<a target=_top>` click, `<link rel=prefetch>`, an `<object data>`; `eval` (`EvalError`), a `Worker` from a blob (error), `serviceWorker.register` (`SecurityError`), `navigator.clipboard.writeText` (`NotAllowedError`). `parent.postMessage` is the one channel that works, by design.

| what the island did | (1) CSP of section 6 | (2) + frame-src etc. in the frame | (3) + the page's `frame-src about:` | (4) + the WebRTC shim |
|---|---|---|---|---|
| `location.href = ` another origin | **1 request** | **1 request** | none | none |
| `<meta http-equiv=refresh>` to another origin | **1 request** | **1 request** | none | none |
| `RTCPeerConnection` to a STUN server | **3 packets** | **3 packets** | **3 packets** | `TypeError`, none |

So a sealed island is, with (4): **no network, no storage, no cookies, no access to the page, no navigation, no script of its own source but what the compiler wrote, no `eval`, no clipboard**, and one channel (messages) the page controls.

**Not bounded, and not measured:** CPU and memory (the `while` loop above), timing side channels, DNS prefetch (it sends no HTTP request, so this method cannot see it), anything a future browser adds, and the next hole of the kind WebRTC was. The sandbox is a list of closed doors; the list is only as complete as the tests, and the build should re-run this script (`reach`) as a check.

The user's preferences do reach the frame: with the page emulating dark and reduced motion, the frame's `matchMedia` said dark and reduced, and a stylesheet in the frame with `@media (prefers-color-scheme: dark)` took the dark `--accent` (`#6ea3ee`). So the hero's palette and its `prefers-reduced-motion` rules work unchanged in the frame, **without a prop**.

## 3. What the frame costs, measured

* **Messages.** Round trip page → frame → page: **1.2 ms** (p50; p95 1.7–2.0 ms) for 16 B and 1 kB, 1.6–1.7 ms for 100 kB; under 4x throttle **8.5–8.8 ms** (p95 12–17 ms). 2,000 messages posted at once took 2.4–2.7 s to be echoed (about 750 a second) at 1x and 16.5 s at 4x. Messages are cheap one at a time and **not** a bulk channel: an island's data goes in as props (state), not as a stream. Posted **right after the iframe is inserted, a message is lost** (0 of 20); posted at the frame's `load` or when the island says it is ready, 20 of 20. The protocol is therefore a handshake: the island posts `ready`, the page answers with the whole current props, and again whenever they change.
* **The hero.** `rocks.js` + `scene.js` unchanged, with the 8,179 bytes of `site.css` rules they need (taken out of `site.css` by the browser's own parser), 4x throttle, 3 s of animation: drawing took **24 ms inline and 25–35 ms in the frame**; 181 frames in 3 s either way, p50 and p95 16.7 ms, **0 frames over 50 ms** in both. The page's own document holds 347 nodes inline and **7** with the frame (the 347 are in the frame's document). The hero is cheap to seal.
* **The pointer.** The page's `hero()` listens to `pointermove` on the window; a frame sees only the pointer inside itself, so the page must forward it. **Corrected by the build (section 11): the reverse is true as well. While the pointer is over the frame the *page* receives no `pointermove` at all (measured: of 4 moves across the frame, 1 reached the island), so the frame's shim reports the pointer inside it and the page adds the frame's offset.** 180 events at 60 Hz for 3 s, 4x throttle: forwarding every event gave a round trip of 58–72 ms (p50) and the *page* 3–11 frames over 50 ms (p95 frame 50–67 ms); at most one per animation frame was no better (7–10 frames over 50 ms); **at most 20 a second** gave 1–3 frames over 50 ms (p95 33–50 ms). The hero's layers already ease `--px` with `transition: transform .25s`, which hides 20 Hz. **Rule: the runtime forwards the pointer at most 20 times a second**, as normalised coordinates of the page's viewport, only while the island is on screen.
* **The cairns.** The page has 11 `.cairn` dividers (3 rocks each). Inline: **15–24 ms** to draw all 11, 15,613 bytes of HTML (5,364 gzipped). As 11 sealed frames at 4x: **875 and 1,237 ms** until all 11 had drawn (and 111 ms at 1x), **168,239 bytes** of HTML (7,173 gzipped: the 11 copies of the runtime compress), 12 documents. **This is the expensive one**: about 50x the time and 11x the bytes of drawing them in the page, for 11 decorations of 3 stones. The reveal on scroll works unchanged, though: an `IntersectionObserver` *inside* a sandboxed frame reports the **page's** viewport (a stone 900 px below the screen has ratio 0; when scrolled to, 1, `rootBounds` null), so the cairns' `.in` class, today set by the page's observer, can be set by the same observer code in the frame (1 of 11 revealed at load, 11 of 11 after scrolling, as inline).
* **Accessibility.** The hero's 347 nodes are shapes with no name: they are **not in the accessibility tree either way** (the page's tree had 6 nodes with `title` only, 6 with `role="img"`, 5 with `aria-hidden="true"`: the iframe itself is the one node). `decorative: true` writes `aria-hidden="true"` on the iframe and removes that node.

## 4. The smallest island API for the real hero and cairns

The fixed decisions: declared, pinned by `sha256`, sealed by default, visible to `authority` and `diff`. The smallest declaration that runs the real files:

```
island Hero {
    script: "assets/rocks.js"   sha256: "ab5fffd8..."      // byte for byte the file cancho-www has
    script: "assets/scene.js"   sha256: "b183de18..."      // byte for byte the file cancho-www has
    script: "assets/island-hero.js" sha256: "..."          // the glue: 15 lines, new
    style:  "assets/island-hero.css" sha256: "..."         // the 8,179 bytes of rules and both palettes
    label: "A stack of granite boulders in front of a blue sun"
    decorative: true
    width: 640 height: 600
    props { pointer: Pointer }
}
island Cairn {
    script: "assets/rocks.js"   sha256: "ab5fffd8..."
    script: "assets/island-cairn.js" sha256: "..."
    style:  "assets/island-cairn.css" sha256: "..."
    decorative: true
    width: 84 height: 58
    props { seed: Int }
}
// in a view:  Hero { pointer: pointer }      Cairn { seed: 3 }
```

* **The pieces, and nothing else:** an **ordered list of hashed scripts**, an optional **hashed style**, `label:` (or `decorative: true` and then none), `width`/`height`, typed **props** (`Bool`, `Int`, `Float`, `String`, and the built-in `Pointer`), typed **events out** (none for these two). No body markup: the glue creates the `<svg>` it draws into. The frame's document is: the policy `<meta>` (section 2), the style, then the scripts in order, each in its own `<script>`.
* **The contract inside the frame** is four names, written by the compiler before the island's scripts: `cancho.props` (the latest props), `cancho.onprops(fn)`, `cancho.emit(name, value)`, `cancho.ready()` (posts `ready`; the page answers with the props). Nothing else is added to the global. The shim also removes the WebRTC constructors (1.2).
* **`rocks.js` and `scene.js` run unchanged.** They need only `window`, `document.body` (for `Rocks.ensureDefs`, which appends the gradients `#gr`, `#shade`, `#halo`, `#speck` that the rocks' `fill: url(#gr)` find in the same document), `document.createElementNS`, and `Scene.draw(svg)`; the same `scripts/make_og.js` use of `Scene.draw` is untouched. Measured: the real files drew the hero in the frame.
* **New code the port needs (not in cancho-www today):** the glue, which is the part of `site.js` `hero()` and `cairns()` that moves: `Scene.draw(svg)`, `--px` and `--py` from `cancho.onprops`, for the cairns `Rocks.rock` for three stones from the `seed` prop and the page's `IntersectionObserver` code for `.in` (measured to work in the frame, 3). About 15 lines each. And `island-hero.css`: the rules of `site.css` for `.defs` (**added by the build: `Rocks.ensureDefs` appends an `<svg class="defs">` to the body, and without `.defs { position: absolute; width: 0; height: 0; overflow: hidden }` it sits in the flow at 300 x 150 and pushes a cairn out of its 58 px frame, where its observer never fires: measured, 0 of 11 revealed until the rule was added, 3 of 11 at load and 11 of 11 after scrolling with it**), `.rock-*`, `.shrub`, `.scene .layer`, `.sun`, `.ridge*`, `.ground`, `.pine`, `.cloud`, `.bird`, `.drop`, the keyframes `sunrise breathe drift glide settle`, `.cairn` and the two palettes (`:root` and `prefers-color-scheme: dark`). Those rules also style the authority animation and the map on the page, so **they exist twice** (once in the page's style, once in the island's); the duplication is the price of a frame that does not inherit the page's CSS.

### What would NOT work unchanged, so that nobody finds out later

1. **`site.js` `hero()`** (listens to `pointermove` on the *window*, divides by the *page's* `innerWidth`/`innerHeight`, skips drawing when `.scene` is off screen by `getBoundingClientRect`). In a frame the window is the frame's; the rectangle is the frame's. It is replaced by the glue and the `Pointer` prop; the off-screen skip becomes an `IntersectionObserver` in the frame (works, 3).
2. **The page's observer for the cairns** (`io.observe(.cairn)` sets `.in` on a *page* element): the element is now inside a frame. Same code, in the glue.
3. **The `.scene` chrome** (28 px radius, ring, shadow, the sky gradient from `--sky` and `--bg`): it is page CSS around the island. Either a `Card`-like wrapper in the program, or the island's body style; not the island's concern.
4. **The page's CSS variables** (`--accent`, `--g1`, `--ridge0`, `--sky` ...): not inherited. The palette lives in the island's style with a dark variant under `prefers-color-scheme` (measured to work, 2). If the page ever lets the reader choose a scheme independent of the system, the frame will not follow it, because the choice is not a media query; that would need a prop. The cancho-www page has no such switch.
5. **Eleven frames for the cairns** (3): works, but is the cost the decision bought. Options that stay inside the decisions: keep 11 sealed `Cairn` islands (the cost above); or lazily give a frame its `srcdoc` when it nears the screen (a hole filled by the script: saves the 168 kB of HTML, costs the frames' content being absent without script and after a delay). Neither was built. A third (draw the cairns to static SVG at build time) needs a JavaScript engine at build time, which `cancho-ui` does not have.
6. **A `Visible`/pointer prop for the cairns:** not needed (the frame's observer sees the page's viewport).
7. **Anything that reads the page** (`document.querySelector('.reveal')`, `getElementById('top')`): a sealed island cannot, by construction.

## 5. The map as an open island

`map.js` (21,760 B) is not a drawing function: it reads and writes **page elements by id** (`#map-svg`, `#map-chips`, `#map-count`), builds the filter buttons, the detail pane, the demo UI with its buttons and terminal, and sets `window.CanchoMap`; `site.js` (line 259) fetches `ecosystem.json` and `demos.json` and calls it. **It cannot run unchanged as the drawing half of the plan in `www.md` 9** (logic in the program, drawing in the island): by reading, about 140 of its 301 lines (the chips, the detail pane, the demo UI) are the logic that the plan moves to cancho-ui.

* **Run unchanged, as an open island that owns its part of the page:** possible only if the page has elements with those ids (`#map-svg`, `#map-chips`, `#map-count`, `#map-fallback`). The program can give a `Section` or `Article` an `id:`; the id is all `map.js` queries, but the *tag and attributes* of the original (`div.chips role=group aria-label`) are not reproducible with the structure elements, so the DOM would differ from today's page. Not recommended.
* **The decided plan needs a rewritten `map.js`** (by estimate about 150 lines: `SPOTS`, `blob`, `granite`, the trails, the `viewBox` tween) that takes `places`, `trails` and the selection as props and emits `Selected(id)`, with the filters, the count, the detail pane and the repository links written in the program. That is a smaller island with the same API as above plus `sealed: false`: the island gets the **host element** (`cancho.host`) and the page's `document`; it declares **`requires Dom`**; it is what `authority` prints as `UNBOUNDED`.
* **Open island API, additions to 4:** `sealed: false`, `requires Dom;` in the component, a `host` element the compiler draws (a `div` with the island's `id`), keyboard focus order that is the page's (the reason the map is open), and an accessible form that the island cannot supply by itself: the **list under the map stays the text alternative** (`island-text-alternative-missing` if it is absent). The island's scripts still come from a declared, hashed list.
* **Cost.** Not measured as a frame (it is not one). It is in the page's document: today the map is 426 nodes of the page's 2,951.

## 6. How `inspect effects`, `diff`, `report` and `authority` say it (designed, not built)

```
$ cancho-ui inspect effects Page
{ "component": "Page", "requires": [ { "name": "Dom" }, ... ],
  "islands": [
    { "name": "Hero",   "sealed": true,  "decorative": true,  "files": [ {"path": "assets/rocks.js", "sha256": "ab5fffd8..."}, ... ],
      "reaches": "nothing but this page, by messages", "props": ["pointer: Pointer"], "events": [] },
    { "name": "Places", "sealed": false, "authority": "UNBOUNDED (runs plain JavaScript in the page's origin)", ... } ] }
```

* **`inspect effects`** lists every island of the component: sealed or open, each script with its `sha256`, props, events, and for an open one `UNBOUNDED`.
* **`diff`**: a new island, a removed one, a changed `sha256` of any of its files (as an asset change: `~ file assets/scene.js: ab5f... -> c901...`), a changed prop or event list, a change of `sealed`. **`authority: expanded`** for an open island added or a sealed one opened (because `requires Dom` appears); **`authority: unchanged` but a line of its own, ranked first**, for a sealed island added or changed (it reaches nothing). The island's *files* are already covered by the asset pipeline of B3 (size, existence, hash); the scripts are text files, so they get `asset-type-mismatch` for a file that is not text/UTF-8 and a size bound.
* **`report`** (the trust boundaries list that foreign functions use): each island is a boundary; an open one is marked `UNBOUNDED`.
* **`test` (replay)**: an island is **not run**; the report says `island Hero: not replayed` (`islands_not_replayed` in the JSON), and an event the island would send is a step of the trace like any other (**corrected by the build: the trace does not record the props sent, they are literals of the program**). The island's behaviour is checked by a Chromium script the page owns.
* **The page's CSP:** `frame-src about:` is added to the page's `<meta>` whenever it has a sealed island (section 1.1), next to the `img-src` a map gets; a program with an *open* island adds nothing (it runs in the page).

## 7. Islands, prerender and hydration

* **A sealed island is a static element of the skeleton, not a hole.** Its `<iframe srcdoc>` is written by the compiler into `index.html` like an `Image`; the script only *posts* props to it. Without script the visitor gets the frame with its style and no drawing (a blank rectangle with the background of the island's style), and the iframe's `title` (the `label:`) — `aria-hidden` when decorative.
* **Measured: under the P1a script (empties `#root` and rebuilds) an island restarts every time the page renders: 4 starts in one load plus three renders; under P1b (fills only the holes) it starts once and is the same node.** P1b is what makes an animated island workable, and an island is the strongest reason for it.
* **The props handshake** (section 3): the frame posts `ready`; the page's runtime answers with the whole current props; later changes post again. The skeleton hash covers the iframe's `srcdoc`, so a changed island is a changed skeleton and the script of another build leaves the page alone.
* **Bytes.** The hero's `srcdoc` attribute is 18,031 bytes in the HTML (3,854 gzipped) for 5,524 + 3,304 + 718 bytes of script and 8,179 of style; the cairns 168 kB for 11 (7 kB gzipped).
* **An open island is a hole**: it is script in the page's document, drawn into a host element the skeleton holds between markers. *(Corrected 2026-10-28: the host element is a static element of the skeleton, as section 12 says, and an open island is subject to `island-rebuilt` like a sealed one: section 13.1.)*

## 8. Rule tags planned (each needs a corpus case when it is built) — *as built: section 11 lists them; the changes from this list are marked there*

`island-undeclared` (a `<script>`, an inline script, a `javascript:` address smuggled through any string), `island-hash-mismatch`, `island-source-missing` (and the asset tags for the files), `island-label-missing`, `island-text-alternative-missing` (an open island that is not decorative has no text alternative element), `island-size-missing`, `island-prop-invalid` / `island-prop-type`, `island-event-undeclared` / `island-event-type` (a message that is not a declared event, or has the wrong type, is dropped and counted: a runtime rule, not a build refusal), `island-open-needs-dom` (`sealed: false` without `requires Dom`), `capability-unused` (the existing tag, for `requires Dom` with no open island), `island-script-order` (a script uses a name no earlier script defines: **not checkable without reading the script, so not offered**).

## 9. What is not measured, and what this design does not claim

* A real phone, Safari, Firefox; screen readers on an iframe; the 4x throttle stands for a slower CPU and nothing more.
* **That the sandbox is complete.** The reach table is 30 attempts; the list of attempts is the thing to extend (the build should run it as a check), and the WebRTC finding is the reason not to trust a short list. The shim that removes the constructors is a defence, not a proof: an island that reaches a pristine `RTCPeerConnection` through some path the 30 attempts do not try (a nested realm is closed by `frame-src 'none'`; no other was found) would not be stopped.
* CPU and memory bounds (the island that loops stalls the page for as long as it loops); timing channels; DNS prefetch.
* Pixel parity of the hero in the frame against the page's inline hero: not compared (the draw is the same files, the stylesheet is a copy; the parity check of the port will compare pixels).
* The glue and the island stylesheet were written for the measurement, not for the port; their size (718 bytes and 8,179 bytes) is what was measured, not what the port will write.

## 11. What was built (PR 1: sealed islands), and what the build corrected above

**Surface.** A top-level declaration, and an instance written like an element:

```
island Stones {
    script: "assets/stones.js" sha256: "2d8c..";   // scripts run in the order written
    style: "assets/stones.css" sha256: "42d0..";   // optional
    label: "Three stones in a row. Click one to pick it.";   // or  decorative: true;
    width: 320;  height: 200;                                  // pixels, 1..4000: the shape before the frame loads
    props { seed: Int; pointer: Pointer; }                     // Bool Int Float String, and at most one Pointer
    events { Picked: Int; Closed; }                            // carries a Bool, Int, Float or String, or nothing
}
...   Stones { seed: 3 on: Picked }                            // literals; the Pointer is never bound; `on: Name` -> `on Name(v)` of the component
```

`examples/islands/` is this program with its files and a trace. **Props are literals, or state fields** *(corrected 2026-10-26: this said "a prop read from state is `island-prop-dynamic`"; the tag is gone, and a sealed island's prop may be a `state` field of the component, as an open island's always was: [`www-port/gaps.md`](www-port/gaps.md) section 5, which the authority animation of the cancho-www page needs)*: a prop read from state reaches the frame when the state changes, and the `Pointer` is fed by the runtime. Islands are declared in the file that uses them (imported modules have their own; the same name in two files is `island-duplicate`).

**The frame.** `<iframe sandbox="allow-scripts" title=".." width height style=".." referrerpolicy="no-referrer" data-cui-island="{..}" srcdoc="..">` is a **static element of the skeleton** (`inspect prerender` lists only the `Text` that reads state as a hole). Its document is: a `<meta>` policy `default-src 'none'; script-src <one sha256 per script, the shim and the ready line>; style-src 'unsafe-inline'; form-action 'none'; base-uri 'none'; frame-src 'none'`, the style, the shim, the island's files **byte for byte** in `<script>` elements in order, and `cancho.ready();`. The page gets `<meta http-equiv="Content-Security-Policy" content="frame-src about:">` (merged with the `img-src` of a map) when a program **uses** an island. **What `frame-src about:` rules out:** every other frame of that page (a video player, a payment form, a map embed by address): the browser refuses it and logs the directive (measured, `scripts/check-islands.js` E: 0 requests to the host, the console names `frame-src`); a frame with a `srcdoc` is not refused. The island's contract is four names, `cancho.props`, `cancho.onprops(fn)`, `cancho.emit(name, value)`, `cancho.ready()`; the compiler ends the document with `cancho.ready()` itself (calling it again is harmless), because the page answers a `ready` with the whole current props.

**Runtime** (`ADAPTER_JS`, about 100 lines, in `app.js` only when a program has an island): one `message` listener; a message is attributed by `event.source`, never by what it says. Props go to a frame when the page registers it and when it says `ready` (so a page whose script is late, and a frame built by script after load, both get them: measured, C). An event is heard when the island declares it, the view hears it (`on: Name`), its value has the declared type (a `String` at most 4096 characters), and the frame has not sent more than 50 in the last second; anything else is dropped and counted (**`island-event-dropped`**, `window.__cui_island_stats`), and nothing is thrown. The pointer: the page sends the normalised viewport position to a frame that declares a `Pointer`, at most 20 a second **for all frames together**, only while the frame is on screen; **a pointer over the frame is reported by the frame's shim** (the page never sees it), and the page adds the frame's offset.

**Rule tags** (all in `spec/diagnostics/README.md`, all reached by a case of `tests/islands_corpus.json` or, for the runtime rule, by `scripts/check-islands.js`): `island-name-invalid`, `-name-conflict`, `-duplicate`, `-entry-duplicate`, `-file-duplicate`, `-path-invalid`, `-hash-invalid`, `-script-missing`, `-too-many`, `-size-missing`, `-size-invalid`, `-label-missing`, `-label-conflict`, `-prop-name`, `-prop-duplicate`, `-prop-type`, `-pointer-twice`, `-event-name`, `-event-duplicate`, `-event-type`, `-source-missing`, `-source-too-large`, `-too-large`, `-hash-mismatch`, `-source-not-text`, `-source-unsafe`, `-instance-children`, `-instance-label`, `-prop-unknown`, `-prop-pointer-bound`, `-prop-bound-twice`, `-prop-dynamic`, `-prop-missing`, `-event-undeclared`, `-event-args`, `-event-handler-missing`, `-event-arity`, `-event-bound-twice`, and at run time `island-event-dropped`. **Changes from section 8:** `island-undeclared` is **not a tag**: nothing interprets a string as markup or script (no `innerHTML`, `eval` or `new Function` in the output; `link-scheme-refused` refuses `javascript:`; a `<script>` and an `onerror` image written as `Text` are text, checked in Chromium, H), so there is nothing to refuse; `island-source-missing`, `-event-undeclared` and `-prop-type` are as planned, `-prop-type` also covers a literal of another type; `island-text-alternative-missing`, `island-open-needs-dom` and `capability-unused` belong to the open island (PR 2) and are not built; `island-script-order` stays not offered.

**Reporting.** `inspect effects` lists `islands` (name, files with SHA-256 and size, label, props, events, `reaches`, and `not_bounded`); `report` lists each island as a `trust` boundary (`kind: "sealed island"`, `tier: "Trust"`) and counts it; `diff` prints `islands` changes **first** and leaves `authority` unchanged (`semantic-diff.md` 12); `test` says `island X: not replayed`. A sealed island is not a capability: `requires` does not change.

**Measured in this PR** (desktop Chromium; `scripts/check-islands.js`, `scripts/measure-islands.js <clone> compiled`; the machine was otherwise idle, timings are of one run unless a range is given):

The island now begins when the props are there; the counts below are from the fixed check, and the 30 attempts of section 2, made with real addresses by `measure-islands.js`, stand as they were.
* The 33 attempts of `tests/fixtures/islands/reach.js` (the list of section 2, with the `eval`/`new Function` and the two WebRTC constructors told apart, and four ways to run a script the compiler did not write added; the page-level `<a target=_top>`, `meta refresh` and `location.href` ones run last, after the answer is sent) from inside a frame the compiler wrote: **0 requests** to another origin, **0** to the page's own, **0 UDP packets** to the STUN socket. `eval` and `new Function` are `EvalError`, `RTCPeerConnection` and `webkitRTCPeerConnection` are `TypeError`, `parent.document` and `localStorage` are `SecurityError`, and an inline `<script>`, a `document.write`ed script, an inline `onclick` and a `javascript:` address that the island adds **do not run** (the policy names scripts by hash). **What the sandbox does NOT guarantee** (also in `inspect effects` as `not_bounded`, and in the PR):

* **Time.** A sealed island that loops stalls the page it is in (measured in section 1: 1,983 ms for a 2 s loop). Nothing bounds CPU; nothing bounds memory.
* **WebRTC beyond the shim.** The constructors are removed in the frame and 0 packets arrive; no other path was found, and none is proved absent. A browser that adds one is a hole the attempts do not try.
* **Timing and cache side channels, and DNS prefetch** (a prefetch sends no HTTP request, so this method cannot see it).
* **Anything after the attempts that were measured.** The list is a list of closed doors; it is only as complete as the checks.
* **What the island shows.** A sealed island can draw anything in its rectangle, including text that looks like the page's; the page does not review pixels. Its `label` is the author's word.
* **Other browsers.** Chromium only; Safari and Firefox treat `sandbox`, CSP in `srcdoc` and cross-origin `IntersectionObserver` as their versions do, unmeasured.
* **Events and props are not authority:** a heard event runs a handler of the program with a value of the declared type, and that handler can do whatever the component's `requires` allow. A flood is capped at 50 a second, not stopped.

**Not built (PR 2 built the open island, section 12):** props of a *sealed* island read from state (*built 2026-10-26: [`www-port/gaps.md`](www-port/gaps.md) section 5*), an island declared in an imported module, and the lazy `srcdoc` for the cairns (the documented fallback of 4.5).

## 12. The open island (PR 2): no sandbox, and it says so

An open island is plain JavaScript that runs **in the page**. Nothing bounds it: it can read and write the whole DOM, the page's storage and cookies, call the network from the page's origin, open WebRTC connections, `eval`. The compiler pins its files by hash and reports it; **it makes no claim about what the island does**, and nothing in this section is a sandbox.

```
island Places {
    sealed: false;                                     // the only difference in the declaration
    script: "assets/rocks.js" sha256: "..";            // the real file, byte for byte, then the drawing module
    script: "assets/map-draw.js" sha256: "..";
    style: "assets/map-draw.css" sha256: "..";
    label: "Map of the projects: each one is a rock.";  // or decorative: true;
    width: 1300;  height: 810;                         // the aspect box the host holds before the script has drawn
    props { places: String; selected: String; kind: String; only_built: Bool; }
    events { Selected: String; }
}
component Ecosystem {
    requires Dom;                                      // island-open-needs-dom without it; capability-unused with no open island
    ...
    view { ... Places { places: data selected: selected kind: kind only_built: only_built on: Selected text: "projects" } ... }
}
```

* **What the program must say.** The component declares `requires Dom;` (`island-open-needs-dom`; `capability-unused` when it declares `Dom` and draws no open island). A non-decorative open island names its **text alternative**, the `id:` of an element of the component, as `text: "projects"` (`island-text-alternative-missing`, `island-text-alternative-invalid`): the drawing is not readable by a screen reader, the element is. The host gets `aria-describedby`. No `Pointer` prop (`island-open-pointer`): the island is in the page and listens to the pointer itself. **Props may be state fields** (`seed: n`), checked against the field's type (`island-prop-source-unknown`, `island-prop-type`), and an open island with such props is used once per component (`island-open-instance-twice`: the page's script gives a state value to an island by its name). A sealed island's props are still literals.
* **What it is on the page.** A `<div role="group" aria-label=".." aria-describedby="..">` in the skeleton, an aspect-ratio box of the declared size, **a static element, not a hole**; the page's script runs the island's scripts (text the compiler read and checked against the hashes, held in `app.js`) into it, each in a function that is given `cancho` = `{ host, props, onprops(fn), emit(name, value), ready() }`, and its style is added to the page once (global: the rules of an open island's style are the page's). A render does not touch the host (the same node, measured). There is **no `frame-src` policy** for it and no policy of any kind: the page's policy is what the program already has.
* **How it is said.** `inspect effects`: `"sealed": false`, `"authority": "UNBOUNDED (runs plain JavaScript in the page's origin; no sandbox)"`, `"reaches": "everything the page can reach.."`, files by hash. `report`: a `trust` boundary of `kind: "open island"` with the same authority. `diff`: the island lines first as for a sealed one, and **`authority: expanded`** for an open island added or a sealed one opened (and `reduced` for the reverse), **even when `requires Dom` does not change** (tested with two programs that both declare it); `Name = sealed -> open` is the line. The diagnostics' wording says "open island" and "runs plain JavaScript in the page", never "isolated", "sandboxed" or "safe".
* **What an open island can reach, measured** (`scripts/check-islands.js` J: the same `reach.js` battery as the sealed frame, from an open island, `nav` off because leaving the page is the page's own navigation; Chromium, local servers): of the 31 attempts that apply, **29 succeed**. `parent.document` and `top.location` (reached: it is the page), `localStorage`, `document.cookie`, `indexedDB` (reached), `fetch` to another origin and to the page's own (sent), `XMLHttpRequest` (answered, as a request: the server saw it), `new Image`, `sendBeacon`, `WebSocket`, `EventSource`, a stylesheet link, a CSS `url()`, a `<script src>`, `import()` (reached: the module ran), a nested `<iframe src>`, `window.open` (opened), `<link rel=prefetch>`, `<object data>` (all tried: **another origin received 14 requests**, the page's own 1), `eval` (`2`), `new Function` (`1`), a worker from a blob (ran), an inline `<script>` it adds, an inline `onclick` and a `javascript:` address (ran), `RTCPeerConnection` to a STUN server (**4 UDP packets**) and `webkitRTCPeerConnection` (constructed). The two that did not work are not the sandbox: `serviceWorker.register('/sw.js')` failed because the test server has no such file, and `clipboard.writeText` is refused to a page with no gesture. The sealed frame, same attempts: **0 requests, 0 packets, every one refused**. Skipped for the open run, because they replace the page they run in: the `<form>` submit and `document.write`. **So an open island is, for these 31 attempts, the page.**
* **Measured: the real map as an open island** (`measure-islands.js <clone> map`): the 24 projects of `data/ecosystem.json`, the real `rocks.js` byte for byte, `examples/map-island/assets/map-draw.js` (the drawing module, 150 lines, with the layout of today's `SPOTS` substituted by the harness), the chips, the count, the detail pane and the list written in cancho-ui (the filters and the list are `Button`s, the list is the text alternative): **24 rocks drawn in 103 ms at 1x and 290 ms at 4x**, 275 nodes in the island and 369 in the page (today's map is 426 of 2,951), `index.html` 7,198 B (2,724 gzipped), `app.js` 42,905 B (13,248 gzipped; today's `map.js` alone is 21,760 B, but this one carries the places and the real `rocks.js`), 0 console errors, 0 requests to another origin. A rock chosen in the island reaches the detail pane (the handler `Selected`), a button of the list reaches the island (state to props, the camera moves), `Services` dims 17 of 24, and **the host is the same node after the renders**. With reduced motion the camera jumps. With script off the host is there, labelled and empty, and so is the list (a `For` is drawn by script): **without script the map and the text alternative are both absent**, which today's page does not have (it draws a fallback). That is a regression of this design the port has to decide on; it is not hidden here.
* **Measured: the port's map** (B2b, `scripts/check-www-reach.js`, in the gate): the same battery (`tests/fixtures/islands/reach.js`: 33 answers; the earlier measurement above counts the 31 that apply to a frame) added as one more script of the **real** `Places` island of `docs/www-port/site/home.cui`, in a copy of the program, in Chromium against two local servers and a UDP socket. **29 of 33 succeed**: it read `parent.document`, `top.location`, `localStorage`, `document.cookie` and `indexedDB`; the other origin received **12 requests**, the page's own origin 1, the STUN socket **4 packets**; `eval`, `new Function`, a `Worker` from a blob, an inline `<script>` it added, an inline handler and a `javascript:` address all ran. The four that did not: `<form>` submit and `document.write` of a script (skipped by the harness: they leave the page), `serviceWorker.register` (`TypeError`: there is no worker file), `clipboard.writeText` (`NotAllowedError`: no user gesture). "Tried" means the call returned and the effect is the count of requests the servers received, not the word. `inspect effects` names exactly one open island, `Places`, as UNBOUNDED, `requires` has `Dom`, and the other 6 declared islands (15 frames) are sealed.
* **Sealed path, unchanged:** the sealed battery runs with an open island on the same page and still gets 0/0/0 (check F); the page still carries `frame-src about:` for the sealed island, and an open island alone adds no policy; the 30 deliberate breaks of PR 1 are re-run and caught, and 19 more (`scripts/breaks/islands-open.json`) cover this section.
* **Rule tags added:** `island-open-needs-dom`, `island-open-pointer`, `island-text-alternative-missing`, `island-text-alternative-invalid`, `island-prop-source-unknown`, `island-open-instance-twice`; `capability-unused` now also covers `Dom`. All reached by `tests/islands_corpus.json`.
* **What this does not claim.** Nothing about what an open island does. Its scripts are run in the page's origin, with whatever a script has there; the hash says *which* file, not that the file is safe. `Dom` is a declaration that reviewers see, not a bound the runtime enforces. A page that wants to bound an open island's network needs a Content-Security-Policy of its own, which this version does not write. In the non-hydrated build (`build` without `--page`) every render rebuilds the host and runs the island again; the hydrated page (`--page`, `--pwa`) does not.

## 13. A frame must be in the static part of the page (found by the port of the cancho-www page, 2026-10-26)

**Measured**: an island instance inside a component that is *not the one the page mounts* (an instance of another component, which draws itself again at every state change) or under a `For`/`If` is a **new `<iframe>` at every
render**: the old one is removed and a new one built, so the frame reloads and forgets what it drew (Playwright: "Frame was detached" at the first click; the example of `examples/port` did not show it because its island is in the
mounted component's static part). A frame in the static part of the mounted component is written into the page's HTML once and **is never rebuilt** (the check holds the element and finds it connected after eight clicks). So the port keeps
the state of the authority animation in `Home` and not in a component of its own. This was a limit that was **not refused** (a program that did the first thing compiled and flickered); **it is refused now, as `island-rebuilt`: section 13.1.**

### 13.1 `island-rebuilt`: refused (built 2026-10-28; the measurement is B2b's, 2026-10-26)

**The rule.** An island instance, sealed or open, must be in the page's own HTML: in the component that is mounted into the page (the program's last, and not one that another component draws), outside every `If` and `For`, and not under anything else the script draws again. Anywhere else the build is refused with `island-rebuilt` (`spec/diagnostics/README.md`). The message says why (the frame would be a new `<iframe>` at every render: measured over 8 renders, **9 added and 10 loads against 1 and 1**) and what to do (put the instance in the mounted component outside every `If` and `For`, and pass what changes as props from that component's state, as the port does). The check is the one `visible:` and `hidden:` use (`visible-dynamic`): the program's skeleton is written, and the number of `data-cui-island` it holds must be the number of instances the component has.

**Measured, before and after.** A scratch copy of `examples/port` with the instance under `If { when: step >= 0 .. }`, 8 renders in Chromium: before, **9 iframes added, 10 loads** (static form: 1 and 1); after, the build is **refused** (exit 1, one diagnostic, `island-rebuilt`), and the static form is unchanged. Why not "keep the frame across renders": an `<iframe>` removed and appended again anywhere reloads (a probe moved a live frame between two `div`s: its script ran a second time), so the element would have to stay in the document while the hole around it is rebuilt, which is keyed reconciliation of the hole's nodes, a design of its own.

**A `For` over a data file** is written out at build (`docs/data.md` section 3): each copy is a static element, so an island in one is **allowed** when what surrounds it is static. Measured: a mounted component with `For { over: data.items(P, "projects") as: p Stones { .. } }` over a file of 3 items builds **3 `<iframe>` elements in the HTML and none created by the script** (`createElement('iframe')` occurs 0 times in `app.js`). The other rules still apply to the copies: with props read from state, two copies are `island-open-instance-twice` (the page gives state to an island by its name), so the copies take literal props. A `For` over a state field or a list literal is a hole, and is refused.

**What changed in the tests** (every program that ran before still does, apart from these fixtures, which were exactly the behaviour refused): the corpus case "an island inside a For" moved from `valid` to the refusals; "the same island in an imported module" (an `island-duplicate` case) now puts its instance in the entry's mounted component, so it still tests the duplicate, and a new case refuses an instance in the imported module's component; `scripts/check-islands.js` part C, which tested what a frame built by the script under an `If` does (the ready handshake, its event), now checks that building that program is refused (exit code 1 and the tag). The four programs that declare islands (the port, `examples/islands`, `examples/port`, `examples/map-island`) are unchanged, and `docs/demo` and the gallery have none. Corpus: one refusal per place (`For`, `If`, `If` inside a `For`, a `Column` under an `If`, a second instance under an `If`, a component that is not mounted, a component another component draws, an open island under an `If`, the imported module's component), two valid cases (islands in a `Column` of the mounted component, a `For` over data), and a test that cuts each of them at every character and leaves out one character at every position (no panic).

**What is not covered, measured.** The plain JavaScript build (`cancho-ui build file.cui`, no `--page`, no `--pwa`) has no HTML for the page, so the script builds every element, an island's frame among them (`createElement('iframe')` occurs once in the output for `examples/port`), and rebuilds the view at every render (the P1a behaviour of section 11, measured there); the rule is checked against the skeleton, which that build does not write, so a program that passes it can still restart its frame at every render **in that target**. It is the same limit with a different cause and is **not refused**: whether a plain build should refuse islands outright is a separate decision. The code that builds a frame by script (`island::emit` and the `[data-cui-island]` scan) is therefore **still reachable**, from that build, and is not removed. The open island under a hole was not measured separately; the rule covers it by the same argument.
