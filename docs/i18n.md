# Internationalization: message catalogs, formatted numbers and dates, plurals, text direction (issue #82)

> **Status: BUILT** (2026-10-24, issue #82). The design (sections 1 to 5) was written first and merged as #129; sections 6 to 8 say what the build made, what it measured and what it corrected in the design. A sentence of the design
> that the build contradicted is corrected in place and says so. Numbers of section 2 measured with `scripts/measure-i18n.js` (Chromium 141 on the `Pixel 7` profile, and node 22 with ICU 77.1 / CLDR 47 as a second engine) on main at 05e190d.

## 1. What exists

A page's text is the string literals of the program, in one language. `grep -rn "Intl\.\|toLocale" crates` finds nothing. The emitted page is `<html lang="en">`, fixed (`pwa.rs`). Numbers print as JavaScript prints them (`semantics.md`,
"Arithmetic is finite"), dates are `clock.now()` milliseconds with no formatting. `lower`/`upper` are ASCII; `fold` has its own tables (`lists.md` section 10) precisely because the engine's answer was not something replay could share.
The default stylesheet is already mostly direction-neutral (flex rows and columns, `gap`); one declaration is physical: `.cui-table th, td { text-align: left }`.

## 2. Measured

### 2.1 Can the page ask `Intl`, and replay say the same text?

Replay is Rust: it cannot call `Intl`. Replay and the page must give the same text, so the question is whether the *engines* agree with each other well enough to be the reference. 15 locales
(`en en-GB de fr es pt-BR ru pl tr ja hi ar ar-EG he fa`), 225 formatted strings (numbers, percent, currency, four date styles, time), plural categories for 0 to 111 and ordinals for 0 to 24, in Chromium and in node:

| | measured |
|---|---|
| numbers, percent, currency | the same in both engines on this grid |
| plural and ordinal categories of every n | the same in both engines |
| dates | **different in 2 of 15 locales**: `en-GB` `full` is `Saturday 24 October 2026` in Chromium and `Saturday, 24 October 2026` in node; `hi` month names differ (`अक्तू॰` and `अक्टू॰`: a spelling that CLDR changed between the two ICU versions) |
| `pluralCategories` | the same set, listed in another order (`one,many,other` and `many,one,other`) |

So two engines built a few months apart already disagree on a date, and a browser the user updates next week is a third. `Intl` is **not** a text replay can promise. The same is true of the machine: with no `timeZone` given, the date of
`2026-10-24T23:30Z` was `10/24/26, 11:30 PM` in a UTC browser and `25.10.26, 12:30` in a browser set to Auckland and German. A page that formats a date must name its zone and its locale, never take either from the machine.

Other things in the output that a table must carry, because a program that compares or measures text would trip on them: French groups with U+202F (narrow no-break space) and writes `26 %` with U+00A0; German `1.234,50 €` has U+00A0 before the sign; Arabic (`ar`) uses
Latin digits but puts a right-to-left mark around `%` and `-`; `ar-EG` and `fa` use other digits (`١٬٢٣٤٫٥`, numbering systems `arab` and `arabext`); Hindi groups by 2 after the first 3 (`12,34,567.891`).

### 2.2 Plural categories

`en de tr hi fa`: `one other`. `fr es pt-BR`: `one many other`. `ru pl`: `one few many other`. `ja`: `other`. `he`: `one two other`. `ar`: `zero one two few many other`. The 112 values tested give every category of every language, so a catalog that gives an Arabic count only `one` and `other` has no text for most numbers. Plural rules are small functions of n.

### 2.3 Right to left

The same markup, `dir="ltr"` and `dir="rtl"` on `<html>` (`lang` `en` and `ar`), viewport 980 px: a `Row` of three buttons has their left edges at `[0, 49, 98]` and at `[939, 890, 832]`: **the flex row reverses by itself**, with no change to the
program or the stylesheet. `margin-inline-start: 8px` moves from the left edge (8) to none (0, it is on the right); `margin-left: 8px` stays on the left. A table header with `text-align: left` stays left-aligned inside a cell that is now at the right
edge: **the one physical declaration of the stylesheet is wrong in a right-to-left page.** `lang` and `dir` can be set at run time (`['ar', 'rtl', 'rtl']` read back, including the computed `direction` of the body).

## 3. The decision

1. **Catalogs, checked at compile time.** A component (or module) holds a clause

   ```
   messages {
       en { title: "Orders"; orders(n): one "{n} order", other "{n} orders"; hello: "Hello, {name}"; }
       es { title: "Pedidos"; orders(n): one "{n} pedido", other "{n} pedidos"; hello: "Hola, {name}"; }
       ar { title: "الطلبات"; orders(n): zero "..", one "..", two "..", few "..", many "..", other ".."; hello: "..{name}"; }
   }
   ```

   and the program says `t("title")`, `t("hello", name)`, `t("orders", count)` where text is expected (`Text { t("title") }`, a `label:`); the key is a **string literal**. The first language is the default. Tags: `message-key-unknown` (a key no language has),
   `message-key-missing` (a language lacks a key another has), `message-hole-mismatch` (the `{name}` holes of a key differ between languages), `message-plural-incomplete` (a language lacks a category its rules need, or has one they do not),
   `message-language-unknown` (a language the tables do not have, section 3.3), `message-call-invalid` (the key is not a literal, or the arguments do not fit the key). A missing translation is a refusal, not an empty string at run time.
   (Added in the build: `message-key-duplicate` and `message-text-invalid` (a brace that is not a hole). Spanish, French and Portuguese have a `many` form, for millions, so their plural messages need three forms, not two.)
2. **Which language.** The program does not read `navigator.language`. A capability `requires Locale;` gives two calls: `locale.current()` (the language in use) and `locale.set("es")` (`true` when the catalog has it). The page starts in the first of
   `navigator.languages` that the catalogs have, else the default; it never stores the choice (that is `Storage`'s business). A trace says `"locale": "es"` for the start and may step `{"locale": "ar"}` for a user's choice; replay reports `document: {lang, dir}`.
   (Corrected in the build: the trace key is `"locales"`, a list like `navigator.languages` (`["ar-EG", "en"]`), matched by primary subtag, because the page matches the same way; and there is no `{"locale": ..}` step: a user's choice is a click, so it is an
   event whose handler calls `locale.set`, which is what the page does. A component with no catalogs speaks English and has no way to change it: to format in German it declares a German catalog, which may hold one key.)
3. **Numbers, dates and plurals are tables, not `Intl`.** Because of 2.1. The compiler holds the data for a fixed set of languages (decimal and grouping symbols, the grouping pattern, the percent pattern, month and weekday names, the date and
   time patterns, the plural rules; **no currency**: a program writes its currency sign around `fmt.number`), and **both** the emitted page and replay use that data, so they agree by construction (the way `fold` does). `fmt.number(x, digits)`, `fmt.percent(x)`, `fmt.date(ms, style)` and `fmt.time(ms)` (the short time: hours and minutes); **dates are always UTC**
   (measured: the machine's zone changes the answer), named by the call. The first set is `en es de fr pt ru ar he ja hi`; a language outside it is `message-language-unknown`. The tables are generated from Chromium's `Intl` by a script (`scripts/gen-i18n-tables.js`) and checked against Chromium again (section 7); where Chromium and node disagree (2.1) the table follows Chromium, and node was not checked
   (corrected in the build: the design said "checked where the two engines agree"; the build checks one engine).
4. **Direction.** `<html lang dir>` follows the language in use (`dir="rtl"` for `ar`, `he`, and any later `fa`/`ur`), set at mount and by `locale.set`. The stylesheet's `text-align: left` becomes `start`. A `Chart` keeps its axes left to right (numbers
   and time run that way in Arabic and Hebrew as well; not measured with a reader). Replay cannot see layout; Chromium checks it.
5. **Plurals** by the rules of 2.2, written as small functions in the tables, checked against `Intl.PluralRules` for 0 to 111 in both engines (they agree today).

## 4. What the build must have

The tags of 3.1; a shared corpus (`tests/i18n_corpus.json`) that replay and Chromium both run: every `fmt.*` result for every language of the set against the strings measured here, every plural category of every language for 0 to 111 against `Intl.PluralRules`,
a catalog with a missing key and a mismatched hole refused; a page in two languages that switches, whose `lang`, `dir` and layout are read in Chromium in `ltr` and `rtl` (the row reverses, the table header aligns to the start, `margin-inline` and not
`margin-left`); deliberate breaks (a table value wrong, the zone taken from the machine, `dir` not set, a plural category missed, a key accepted when missing); `examples/i18n` (two languages, a formatted number and date, a plural), checked as a page and
through the `--pwa` service worker; a watchdog in every script that can hang.

## 5. Not measured, and open

Firefox and Safari (only Chromium is installed here, so "across engines" means Chromium and node's ICU); a screen reader's voice choice from `lang`; mixed-direction text fields; a language the user types in that is not the page's; collation and sorting (`sort` is by code unit today); Turkish `lower`/`upper`; time zones other than UTC;
calendars other than the Gregorian (the default calendar of `fa` is `persian` in node, `gregory` for the other 14 locales of the grid; Chromium's answer for `fa` and the Hijri calendar were not measured); currencies beyond a symbol and a pattern per language; hyphenation; the cost of the tables in the page (to be measured with the build).

## 6. What was built

* **Language.** The `messages` clause (`syntax`: `MessageCatalog`; `ir/src/messages.rs` checks it and the calls), `requires Locale;` (no bound), and the calls `t(key, ..)`, `fmt.number`, `fmt.percent`, `fmt.date`, `fmt.time`, `locale.current()`, `locale.set(lang)`. All seven need `Locale`
  (`capability-missing`); it appears in `requires`, `inspect effects` and `diff` like any capability, so "this release can change the page's language" is a line. Eight tags (`spec/diagnostics/README.md`), each reached by a test.
* **Data and algorithms in Rust** (`ir/src/i18n.rs`, data `ir/src/i18n_data.rs` generated from Chromium 141): the decimal rounding is done on the shortest decimal digits of the double and rounds half away from zero (what `Intl` does: `1.005` at two places is `1.01`, where `toFixed`
  says `1.00`); a percent moves the point two places in those digits (`0.145` is `14.5`, which rounds to `15`).
* **The same in the page** (`codegen-web/src/i18n.rs`): the data of the languages the module uses is embedded as JSON, the steps are JavaScript; `t(..)` isolates each hole (section 7.4). `<html lang dir>` are set at mount and by `locale.set`.
* **Replay** (`replay/src/locale.rs`): the language in use, chosen from the trace's `locales`; `document: {lang, dir}` in the report.
* **Stylesheet:** `text-align: start` in tables.
* **Corpora:** `tests/i18n_corpus.json` (6,120 answers of `Intl` for 10 languages: numbers, percents, dates, times and plural categories, generated by `scripts/gen-i18n-corpus.js`), `tests/i18n_pages.json` (a program in English, Arabic and Russian with 6 cases and 33 steps).
* **Example and gallery:** `examples/i18n` (English, Arabic, Russian), now a tile of the landing page; the coming-soon tile for #82 is removed.
* **A defect found and fixed on the way:** `credential::check_call` read any call named `set` as `credential.set` (it checked the second segment only), so `locale.set(x)` was refused as a misuse of `credential.set`, and `storage.set` passed only because it also has two
  arguments. It now looks at the first segment too.

## 7. Measured at the build

### 7.1 The formats against `Intl`

* `crates/cancho-ui-ir/tests/i18n.rs` (Rust) and `scripts/check-i18n.js` (27 checks, about 9 s; the emitted JavaScript, in Chromium) each hold 6,120 answers to what Chromium's `Intl` answered when the corpus was written: all agree.
* **Fresh input against `Intl` in the same Chromium** (so the corpus cannot have been fitted to): 53,006 answers, none different: 4,000 random numbers at 0 to 6 places and as percents in ten languages, 7,500 random instants in the years 1000 to 9999 in four date styles and the time, and the plural category of every
  count from 0 to 3,000 and of 12 large ones.
* **Two things Chromium does that the corpus first caught, now in the generator:** `format()` writes U+0020 where `formatToParts()` has U+202F in a date's text (a V8 compatibility rule: Russian `2026 г.` has an ordinary space); a minus sign comes with a direction mark before it in Arabic (`‎-1,234`). A negative value that rounds to zero keeps its sign (`-0.00`), as `Intl` does.
* **Plural categories:** `Intl.PluralRules` gives `one` to **-1** (it reads the size), and to **1.5** in French, Portuguese and Hindi. The language takes the size and calls a count that is not a whole number `other`; the 1.5 case is not modelled (section 8).
* What the language leaves out on purpose, so `Intl` does not decide it: a value smaller than 1e-6 in size is written as zero, 1e21 and more, a non-number and more than 6 places are the empty text, dates outside the years 1000 to 9999 are the empty text.

### 7.2 Right to left, in the built page

At 412 px (Pixel 7): the three buttons of a `Row` have left edges `[16, 95, 167]` in English and `[325, 253, 170]` in Arabic, with no change to the program or the stylesheet; a `.cui-table` header's text sits 8 px from the start of its cell and 123 px from the end, in both directions
(before the change to `start` it stayed at the left in Arabic); switching Arabic to English turns `dir` back and the row with it; no page scrolls sideways in either direction.

### 7.3 The page in a browser of another language

With the browser's language Russian, the example starts in Russian, says `3 заказа`, `Итого: 1 234,50`, `24 октября 2026 г., 15:05`, `26 %` (with a no-break space); in Arabic 3 orders is `3 طلبات` and 11 is `11 طلبًا` (the `many` form); in English `11 orders`,
`Total: 1,234.50`, `Due October 24, 2026 at 3:05 PM`. Installed with `--pwa` and the server stopped, the page starts and formats the same: the data is in the page, nothing is fetched. A browser list with no language the page has gets the first catalog.

### 7.4 Isolating a value put into a sentence (this was open in the design)

`scripts/measure-i18n.js --bidi`: a value inside a sentence of the other direction. In an Arabic sentence the values `C#7!`, `(B)` and `-5` do **not** read as written (the punctuation moves to the other side of the value), and with U+2068 before and U+2069 after they do; `A-12`, `12`, `x.y` and
`Ada Lovelace` read as written either way. The reverse holds too: in an English sentence `(ب)` and `ب!` are rearranged without the isolates and read correctly with them. So `t(..)` wraps **every hole of a plain message** in U+2068 and U+2069, in every language (a plural's count is digits and is not wrapped).
The cost is two invisible characters in the text of a message with holes: a program that compares or measures such a text sees them. Not measured: whether a screen reader says anything for them (no screen reader was run).

### 7.5 The deliberate breaks

`scripts/breaks/i18n.json`: 33 breaks, each applied to the source, the compiler rebuilt and three checks run (the Rust formats and plurals, the Rust language and replay tests, `scripts/check-i18n.js`). Every break is caught **by a check that failed on its own**; the harness now kills a
check that does not end within 15 minutes and reports the break as `HUNG`, not caught, and a break that does not compile as `BUILD`, not caught. The first full run caught 30 and **missed 3, which were bad tests and a bad break, not a bad check**: flooring a negative fraction of a millisecond instead of truncating it
(the corpus had no instant on the far side of a minute: three were added), the percent computed by multiplying (my break was nearly a no-op: replaced by one that really multiplies, and `0.145` then gives 14, not 15), and the language tag split at `-` only (my test used `EN_gb`, which falls back to English anyway: `de_AT` was added). The three were
re-run alone and each is caught. Of the 33: 8 by the Rust format tests only, 10 by the Rust language tests only, 4 by both, 3 by the Rust language tests and Chromium, 8 by Chromium only. They cover: rounding a half down; grouping (the minimum, the Indian pattern); the plural rules of Spanish, Russian and Arabic; the
weekday, midnight on a twelve-hour clock, a two-digit year, the sign of a negative that rounds to zero, a fraction of a millisecond; the checks of the catalogs (a duplicate language, holes that differ, a missing plural form, a key one language lacks, a call with the wrong arguments, a plural form with another hole); the capability of `fmt.percent`;
the isolates in replay and in the page; the language tag's primary subtag in replay and in the page; `locale.set` accepting any language; Arabic left to right; `dir` the wrong way round in the page; the page's rounding, Russian rule, weekday and minus; the table header aligned left; the document not set at mount.

## 8. Not done

Currency; the Persian and Hijri calendars and every calendar but the Gregorian; time zones (dates are UTC); the plural of a fraction (`1.5` in French, Portuguese and Hindi is `one` in CLDR; here `other`); other languages than the ten, and regional variants (`en-GB` writes `24/10/2026` where `en` writes `10/24/26`; the page
uses the primary subtag); collation and sorting; Turkish case; hyphenation; Firefox and Safari (only Chromium here; node's ICU disagrees with Chromium's in two places, section 2.1, and the tables follow Chromium); a screen reader's voice choice from `lang`; the static `<html lang="en">` of the page before the script runs (the language is set at mount);
a `Chart`'s axes in a right-to-left page (left to right, not checked with a reader); a text field in which the user types the other direction; the size of the data: measured at the build, a trivial program that speaks all ten languages is 20,008 bytes (4,770 gzipped) against 6,686 for the counter; `examples/i18n` (three languages, their texts, a screen) is 24,341 bytes (6,338 gzipped).
